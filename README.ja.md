# 縁側（Engawa）

[English README](README.md)

だれでも自分の言語で読める、ご近所の掲示板です。災害のときは、水、避難所、配給の情報が、同じ場所に、自分の言葉で届きます。武蔵小杉のマンションでは、断水のお知らせは日本語の紙でエントランスに貼られ、それ以外の情報は LINE や WeChat の閉じたグループの中にあります。地震のあとには防災行政無線が給水の場所を流しますが、屋外ではよく聞き取れません。日本語が読めない住民も、放送が聞こえない住民も、そのどこにも届いていません。縁側では、だれでも手元にあるもの（紙のお知らせの写真、チャットのスクリーンショット、数行の文章、スピーカーで聞いた内容）を入れるだけで、市の放送文は自動で届きます。Claude が内容を読み取り、個人情報を取り除き、別々の出どころから来た同じ情報を1枚のカードにまとめ、日本語・英語・中国語・韓国語・ベトナム語・やさしい日本語で書きます。読む人は自分の言語で質問でき、答えはカードを引用し、情報がなければ「まだ情報がありません」と答えます。

**公開中:** https://engawaboard.com 。日本地図の上に6つの掲示板があり、どれも町丁目の範囲と、市や区の一覧から取った避難所・給水拠点・目印を既知の場所として持ちます。[武蔵小杉](https://engawaboard.com/b/musashikosugi)（川崎市中原区、23の町丁目、14か所、最初の掲示板）、[溝の口](https://engawaboard.com/b/mizonokuchi)（川崎市高津区、14の町丁目、20か所）、[渋谷](https://engawaboard.com/b/shibuya)（渋谷区、11の町丁目、19か所）、[上野](https://engawaboard.com/b/ueno)（台東区、17の町丁目、18か所）、[札幌 大通](https://engawaboard.com/b/sapporo)（札幌市中央区、45の町丁目、21か所）、[博多](https://engawaboard.com/b/hakata)（福岡市博多区、13の町丁目、26か所）。Built with Claude: Japan 2026（2026年11月2日から8日）の期間中に Claude Code が書きました。このリポジトリの内容はすべて期間中に作ったものです。 町丁目と既知の場所の名前は読む人の言語で表示し、街の表示は日本語なので日本語の名前を続けて示します。

## 2分で試す

1. [武蔵小杉の掲示板](https://engawaboard.com/b/musashikosugi)を開き、右上で言語を選びます。
2. 「お知らせを入れる」から「サンプルで試す」を選び、紙のお知らせの写真、チャットのスクリーンショット、貼り付けた文章のどれかを入れます。どれも架空のテスト素材です（名前や番号は作りもの、場所は実在の公共施設）。待っている間のカードに実際の処理の段階が表示され、10秒から15秒ほどで日本語・英語・入力の言語のカードが出て、残りの言語は数秒後に追いつきます。サンプルは本番の掲示板にテスト用のカードを1枚増やします。
3. 「この掲示板に質問する」で「水はどこでもらえますか？」と聞くと、答えがカードを引用します。引用をタップするとカードが開きます。「避難所に猫を連れて行けますか？」と聞くと、まだ情報がないと答えます。
4. カードを開いて「このカードを共有」から「リンクをコピー」か「文章としてコピー」。リンクには自分の言語（`?lang=`）が入るので、LINE や WeChat のプレビューも共有した人の言語で表示されます。
5. 「一覧」を「場所別」に切り替えると、カードが既知の場所ごとにまとまり、住所、避難所の最新の状況、「地図で開く」が出ます。
6. 同じ共有パネルの「6言語のお知らせを印刷」で、掲示板の QR コード付きの A4 のお知らせができます。日本語の原本の横に貼るためのものです。掲示板全体のポスターは [/b/musashikosugi/poster](https://engawaboard.com/b/musashikosugi/poster) です。
7. 掲示板の上の「通知を受け取る」を押すと、ブラウザが一度だけ確認し、それ以降は危険・公式のお知らせ・避難所・水の公式カードと、災害時モードへの切り替えが、サイトを閉じていても自分の言語の通知で届きます。

## デモの流れ

武蔵小杉に避難指示が出て、防災行政無線が流れます。市の防災無線メールが掲示板の公式受信口に届き、6言語の公式カードになり、掲示板はひとりでに災害時モードに切り替わります。上部に赤い帯が出て、公式と危険のカードが先頭に、続いて水・避難所・医療が並び、投稿パネルでは「防災無線を聞いた」がいちばん上に来ます。佐藤さんが小杉小学校の入口に貼られた給水のお知らせを撮って入れると、10秒ほどで、3台のスマートフォンにカードが出ます（日本語と英語はすぐに、中国語は数秒後に）。場所、14時から16時、容器持参、そして「公式のお知らせ（未確認）」の表示です。チェンさんが「駅前のコンビニが開いていて水がある」という WeChat のスクリーンショットを入れると、佐藤さんには日本語で「人から聞いた情報」として届き、画面の名前は伏せられています。続いて同じ給水所についての LINE のスクリーンショットとベトナム語の Facebook 投稿が届きますが、新しいカードは増えず、最初のカードが「情報源 3件」になります。

マリアさんが英語で、水はどこでもらえるか、避難所に猫を連れて行けるかを聞きます。答えは給水のカードを引用し、猫についてはまだ情報がないと言います。だれかが「2時間後に M8 の余震」というデマを入れても、投稿した人には「まだ公開していません。確認が必要です。」と出て、管理用リンクを持つ人が見るまで掲示板には載りません。マリアさんが列の写真に「いま列は短い、10人くらい」と添えて入れると、佐藤さんには日本語で「本人が見た情報」として届きます。あとから開始が15時に変わったお知らせが入ると、カードはそのまま更新され、古い時刻が「以前の情報」として残ります。「場所別」に切り替えると、小杉小学校の下にその学校のカードが住所と避難所の最新の状況つきでまとまり、「地図で開く」でマリアさんはそこへ向かえます。

## しくみ

**処理の流れ。** Claude が提案し、コードが決めます。

1. **投稿。** ブラウザが写真を再エンコードし（EXIF は消えます）、サーバーがもう一度メタデータを取り除いてから保存します。ブラウザはデータベースの鍵を一切持ちません。
2. **抽出**（`lib/claude/extract.ts`、`claude-opus-5-5`、画像入力、構造化出力）。事実、カテゴリ、掲示板の既知の場所に正規化した場所、時刻、出どころの種類、リスクの印、そして日本語・英語・入力の言語のカード。個人情報は［名前］のような置き換えになります。チャットのスクリーンショットは名前とアイコンを塗りつぶし（`lib/claude/mask.ts`）、元の画像は消します。
3. **照合**（`lib/claude/reconcile.ts`、`claude-opus-5-5`、構造化出力）。候補のカード（同じ掲示板・カテゴリ、同じ場所か場所なし、有効期限内、最大20件）はコードが選び、Claude が新規・統合・更新・食い違い・保留のどれかを提案し、コードが適用します。
4. **翻訳**（`lib/claude/translate.ts`、`claude-opus-5-5`、構造化出力）。カードが掲示板に出たあとで、残りの言語を埋めます。
5. **質問**（`lib/claude/ask.ts`、`claude-sonnet-5-5`、Citations）。公開カード1枚を1文書として読む人の言語で渡し、引用をコードがカードに結び直します。カードのない掲示板には Claude を呼ばずにコードが答えます。質問は保存しません。

コードが毎回確かめること：出力が JSON スキーマ（`lib/claude/schemas/`）に合っているか。掲示板にない場所 ID は null にする。電話番号やメールアドレスが残っていれば抽出も翻訳も丸ごと捨てる。元の文の置き換え（［名前］など）が各言語に残っていなければ、その言語を捨てて次の機会に訳し直す。統合や更新の相手は、コードが渡した候補の中にあること。信頼の順位（公式、本人が見た、人から聞いた）はコードが守り、弱い出どころからの更新は食い違いとして両方を並べる。リスクの印がついた事実（デマ、個人の事情）は管理者のために保留する。書き込むのは決められた項目だけ。「公式に確認済み」は管理画面からしか付けられない。画像やメッセージの中の指示は、指示ではなくデータとして扱う。カードには出どころの種類、出どころの数、変わった時刻、前の内容、食い違う内容、読んだ人の「まだ正しい」「もう違う」の数、そしてカードができるまでの経緯（各出どころ、照合での Claude の判断と理由、管理者の確認）が出ます。一度開いた掲示板は、電波がなくても最後に見た内容で読めます（`public/sw.js`）。

**市の放送が届く3つの道。** 防災行政無線は日本語だけで屋外では聞き取りにくい一方、市や区はその文面を公開しています。3つの道はどれも掲示板ごとの秘密の鍵と送信元の許可リストつきで `POST /api/b/<slug>/inbox` に届き（[docs/INBOX.md](docs/INBOX.md)）、そこから来た事実はコードが「公式」「市の防災無線メール」とします。管理者が確認するまでは未確認のままです。

- **メールの中継**（川崎市は11月4日から、福岡市は11月5日から）：防災行政無線と緊急情報を選んで登録したメールニュースかわさきと、福岡市防災メール（緊急情報）が Gmail に届き、Cloudflare Email Routing のアドレスに転送され、Email Worker がその市の掲示板に掲示板ごとの鍵で送ります（川崎市のメール1通は武蔵小杉と溝の口に、福岡市のメールは博多に届きます）。
- **ポータルの読み取り**（渋谷区、11月5日から）：`workers/shibuya-portal/` の Cloudflare の定期実行 Worker が、区の防災ポータルの放送内容を5分ごとに読み、新しい放送を古い順に掲示板へ送ります（テスト18件）。読み取りには区の了承を先にいただく前提です（[docs/BOARDS.md](docs/BOARDS.md)）。
- **直接の POST**：文面を持っているどのシステムからでも、JSON `{from, subject, text, received_at}` で送れます。

上野（区のメール配信）と札幌（公開の JSON フィード。市に放送文はありません）は [docs/BOARDS.md](docs/BOARDS.md) に調べた内容があり、まだつないでいません。

近所の人が「防災無線を聞いた」を押し、ブラウザの音声認識が書き起こした文を直してから送ることもできます。これは常に「人から聞いた情報」の扱いで、市の文面が届くと照合が統合し、カードは市の言葉に置き換わります。

**通知**（マイグレーション 0010、`lib/push/`、`pnpm check:push`）：VAPID 鍵を使う Web Push です。「通知を受け取る」を押した読者には、危険・公式のお知らせ・避難所・水の公開された公式カード、防災無線の入力や公式受信口から来た危険のカード、そして災害時モードへの切り替えが、その読者の言語で届きます。サーバーは投稿者への応答を返したあと、60秒の枠の中で送ります。プッシュサービスに渡るのは暗号化した中身だけで、掲示板が持つのは購読の情報だけです（[docs/PRIVACY.md](docs/PRIVACY.md)）。

**災害時モード**は掲示板の状態です（マイグレーション 0009、`lib/cards/mode.ts`、`pnpm check:mode`）。管理者は理由つきで切り替えられます。公式受信口に届いた市のメールが、危険・公式のお知らせ・避難所のいずれかのカテゴリで公開カードになり、緊急の語（避難指示、避難命令、緊急安全確保、警戒レベル4・5、津波警報、特別警報、震度5弱以上）を含むと、平常時の掲示板は自動で切り替わります。解除のお知らせや、訓練・想定の放送だと書かれているものでは切り替わりません。近所の人の投稿では、何が書いてあっても切り替わりません。自動で切り替わった場合は、新しい公式の緊急カードが7日間なければ平常時に戻り、管理者が切り替えた場合は管理者が戻すまでそのままです。

設計とその理由は [docs/PLAN.md](docs/PLAN.md) にあります。

## Claude Code での作り方

このリポジトリのコードはすべて Claude Code が書きました。セッションごとのモデル、やったこと、計測、人の判断が必要だったことは [docs/DEVLOG.md](docs/DEVLOG.md) にあり、ここはその要約です。

**役割分担。** 計画とレビューを担う `claude-fable-5-1` のセッションがひとつあり、キックオフの夜に `CLAUDE.md`、`docs/PLAN.md`、プロンプト、JSON スキーマを書き、その後はすべての実装セッションの指示書を書き、すべてのプルリクエストをレビューし、指摘を統合ブランチで直し、人の承認を得てマージしました。実装は、11月3日未明の2つのセッション（照合と管理画面、質問と共有と評価）、1日目の後半（`/model` で切り替え）、そして11月4日10時以降のすべてのセッション（オフライン、読者の確認、ノートPC向けレイアウト、防災無線、場所と地図、トップページ、災害時モード、渋谷の掲示板、ポータルの読み取り、マーク、11月5日に加えた4つの掲示板（溝の口、上野、札幌 大通、博多）、Web Push、掲示板ごとのピンを置いたトップページの地図、町丁目の名前の5言語表示、新しい5つの掲示板のサンプルのカード、この README）が `claude-opus-5-5` です。その間の1日目の前半、G の項目、11月4日朝の機能は、週の利用枠が許す範囲で `claude-fable-5-1` が実装しました。DEVLOG の各項にモデルが書いてあります。

**並行するセッションと、レビューを通した統合。** 実装は2つか3つのセッションが同時に、それぞれ別の git worktree とブランチで進め、指示書に担当ファイルを重ならないよう書き込んだので、ブランチは衝突なくマージでき、プルリクエストを1本ずつレビューできました。`main` に入る前には、レビュー担当のセッションが読み取り専用のサブエージェントですべてレビューし（そのチェックリストは11月4日に `.claude/agents/reviewer.md` になりました）、指摘の修正は統合ブランチ（PR 3、7、11、15、18、21、26、27、30、33、40、42、43）で入れています。1週間で50本、うち49本をマージし、1本は差し替えました。凍結時点に `v1.0-hackathon` のタグを付けています。

**本番でどのモデルが何をするか、その根拠となった計測**（フィクスチャによる評価は [docs/EVAL.md](docs/EVAL.md)、詳細は DEVLOG）：

| 処理 | モデル | 根拠 |
|---|---|---|
| 抽出 | `claude-opus-5-5`、effort low | Sonnet 5.5 との比較（11/03）：Opus は 98/100 項目、作り話 0。Sonnet は 97/100、作り話 4（避難所の注意書き1枚を5枚のカードに分けた）、3秒速い。Fable 5.1 との比較（11/04）：Opus は 100/100、中央値 14.0 秒。Fable は 99/100、中央値 22.6 秒、出力トークン 45% 増、単価 2.5 倍 |
| 翻訳 | `claude-opus-5-5`、effort low | 11/04 に抽出から分け、最初のカードが出るまでを 23 入力の中央値で 13.0 秒から 8.3 秒に短縮。Sonnet も 100/100 で約2秒速かったが、翻訳の間カードはすでに掲示板に出ている |
| 照合 | `claude-opus-5-5`、effort low | 受け入れテストのケースで Sonnet と同じ判断、約1秒遅い（中央値 3.0 秒と 2.0 秒）。統合を誤るとカードが黙って消えるので、1秒より重い |
| 質問 | `claude-sonnet-5-5`、Citations、effort low | 人が待っている。本番の掲示板で 1.8秒から3.4秒。Citations は構造化出力と併用できないので、引用された文をコードがカードに戻す |
| 塗りつぶし | `claude-opus-5-5`、画像入力、effort medium | 名前とアイコンを 100% 覆うことが条件。5枚のスクリーンショットで 50/50 の枠。最初は 40/50 で、プロンプトと余白を2回直した |

どの呼び出しもシステムプロンプトと掲示板の情報（既知の場所と別名）をキャッシュし、時刻と入力を最後に置くので、2回目以降は抽出1回あたり約5,700トークンをキャッシュから読みます。Claude の呼び出しを書いたり変えたりする前には、記憶に頼らず `claude-api` スキルで SDK の正確な形を確認しました。

**評価の最新の数字。** 11/04、渋谷の場所の注記が掲示板の情報に加わったあとの `pnpm eval`：16入力で 105/105 項目、個人情報の漏れ 0、作り話 0、リスクの印 16/16、6言語そろい 16/16、最初のカードまで中央値 9.3 秒（p90 10.8 秒）。`pnpm eval --reconcile`：11/11 の段階（新規4、統合6、更新1）、コードによる上書き 0。`pnpm eval:mask`：50/50 の枠。11/03 以降のモデルの判断には、どれもこのどれかの計測があります。

**このリポジトリの Claude Code の設定。**
- `.claude/settings.json`：`Edit|Write` の `PostToolUse` フックが、書いたばかりのファイルに `scripts/guard.ts` を走らせます。ダッシュ（全角ダッシュや二分ダッシュ）があるか、5つのメッセージファイルのキーがそろっていなければ終了コード2で止まり、指摘がそのままセッションに返ります。レビューする側が気をつかうべきでない2つの規則です。`pnpm guard --all` でリポジトリ全体にかけられます。
- `.claude/skills/acceptance-run/SKILL.md`：実装セッションが毎回作り直していた受け入れテストの手順です。試験用の掲示板のコピー（`pnpm board:throwaway create|delete`）、空いているポートの開発サーバー、実際の投稿の経路、DEVLOG 用の表、そして作ったものすべての削除。本番の掲示板にはテストの入力を入れません。
- `.claude/agents/reviewer.md`：マージ前に毎回走らせる読み取り専用のレビュー用サブエージェントです。プライバシーを最初に見て（経路が何を外に出すか、Claude の出力をデータとして扱っているか、文字列がすべて `t()` を通るか、16px の文字と 44px の押せる範囲）、ファイルと行つきの指摘を重い順に並べ、最後に判定を出します。
- 見た目の確認は Claude デスクトップアプリの内蔵ブラウザと、Playwright のヘッドレス Chromium で、390px と 1280px で行い、コントラストと大きさの計測は DEVLOG にあります。

**人が必要だったこと。** アカウントと秘密情報（Anthropic、Supabase、Vercel）、engawaboard.com の購入と DNS、Gmail の中継と市のメールの登録（川崎市、福岡市）、VAPID 鍵、ほとんどのマイグレーションの適用、キックオフの夜の判断（名前、ホスティング、最初の掲示板、最初は通知を作らない、照合はエージェントのループではなく1回の呼び出し）とその後の判断（5つの掲示板の追加、地図は都道府県の塗りではなくピン、通知は公式カードと災害時モードの切り替えだけ）、アクセントの色とマーク、そしてマージ前の承認。人はセッションと中国語で話しました。

## プライバシーと安全

- 正確な位置はスマートフォンから出ません。選んだ場合だけ町丁目のコードを送り、「自己申告のエリア」と表示します。
- 名前、電話番号、部屋番号、チャットの ID、ナンバープレートは置き換えます。チャットのスクリーンショットの原本は表示せず、処理が終われば消します。
- すべての行とファイルに `purge_after` があり、毎日の処理で消します。質問は保存しません。
- アカウントはなく、検索エンジンにも載りません。ブラウザのランダムな ID で上限と反応を数えます。
- Claude の出力はデータです。スキーマ、候補の確認、信頼の順位はコードが守り、危うい事実は人が見るまで保留します。
- 保存期間の表と原則の全体：[docs/PRIVACY.md](docs/PRIVACY.md)。

## 手元で動かす

必要なもの：Node.js 20 以上、pnpm 10、Supabase のプロジェクト、Anthropic の API キー。

```bash
pnpm install
cp .env.example .env.local      # 各キーを記入。用途はファイル内のコメントにあります
pnpm db:migrate                 # supabase/migrations のすべてのファイルをセッションプーラー経由で適用
pnpm db:seed --token-file .env.admin-token.local   # 6つの掲示板、既知の場所、サンプルのカード
pnpm dev                        # http://localhost:3000/b/musashikosugi
```

- `pnpm db:seed --board shibuya` で1つの掲示板だけ、`--dry-run` で接続せずに書く内容を表示します。掲示板は `supabase/seed/boards.json`、境界は `lib/geo/<slug>.json` から読みます。
- 管理画面：`ADMIN_TOKEN` を設定し（`openssl rand -hex 16`）、`/api/b/<slug>/admin/enter?token=<ADMIN_TOKEN>` を一度開くと、その掲示板の管理画面用に12時間の HttpOnly クッキーが残ります。設定しなければ管理画面はありません。
- `SUPABASE_URL` がなければ、掲示板はシードのファイルから読み取り専用で表示され、UI の作業には十分です。
- 通知には `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT` が要ります（`npx web-push generate-vapid-keys`。subject は `mailto:` か `https:` の連絡先）。なければ掲示板に「通知を受け取る」は出ず、管理画面に通知がオフだと表示されます。
- テスト用の掲示板のコピー：`pnpm board:throwaway create <slug>`、終わったら `pnpm board:throwaway delete <slug>`。シードの掲示板の名前は受け付けません。
- 確認：`pnpm typecheck`、`pnpm lint`、`pnpm guard --all`、`pnpm check:mode`、`check:places`、`check:inbox`、`check:boards`、`check:placeholders`（API 不要）、そして `pnpm eval`、`pnpm eval --reconcile --now 2026-11-03T10:00:00+09:00`、`pnpm eval:mask`（API を使う）。
- 公式受信口を手で試す：[docs/INBOX.md](docs/INBOX.md) の curl。

## テスト素材

`fixtures/` には処理と評価のための入力があります。紙のお知らせ、チャットや SNS のスクリーンショット、文章で、11/03 に Claude Code が Playwright で描画し、`expected/` の正解と塗りつぶしの枠を添えました。人物、名前、ハンドル、電話番号、部屋番号はすべて架空で、紙のお知らせにはすべて「訓練用・想定シナリオ」の印があります。場所の照合を試すため、武蔵小杉付近の公共の場所だけは実在です。そのうち3つは `public/samples/` にあり、掲示板のサンプルになっています。由来は [fixtures/README.md](fixtures/README.md) にあります。`fixtures/demo/` には、新しい5つの掲示板のサンプルのカードのもとになった入力があります。11/05 に同じ方法で作ったもので、架空の町会などのお知らせ5枚（印なし）、名前と電話番号を仕込んだチャットのスクリーンショット1枚、文章10本です。処理が作ったカードは `supabase/seed/sample_cards.json` にあり、まだ誰も投稿していない掲示板に表示されるものです。実在の公共の場所での架空の催しです。

## イベントのあと

縁側は二つの層で運営する考えです。全体の運営者が掲示板をつくり、市や区の放送をその掲示板に一度つなぎ、マイグレーションを適用します。それぞれの掲示板には、もともとお知らせを貼っている地域の管理者（自治会、マンションの管理人、区役所の窓口）がつき、その掲示板の管理用リンクで公式のカードの確認、ふさわしくないものの非表示、災害時モードの切り替えを行います。新しい街に要るのはコードではなくデータで、手順は [docs/BOARDS.md](docs/BOARDS.md) にあります。いまは運営者がひとりで、管理用のトークンもすべての掲示板で共通です。掲示板ごとの管理用リンクが次の段階です。読む人向けには [about ページ](https://engawaboard.com/about) が5言語で同じことを説明しています。
